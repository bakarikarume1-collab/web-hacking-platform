OWASP Top 10 & Web Exploitation

This is the most important stage in web security learning. Here you will understand how real-world vulnerabilities work, how attackers exploit them, and how developers fail to secure applications.

Intermediate Level

What is OWASP?

OWASP (Open Web Application Security Project) is a global organization that defines the most critical security risks in web applications.

The OWASP Top 10 is used by:

  • Security engineers
  • Bug bounty hunters
  • Penetration testers
  • Software developers

Why OWASP matters

Most real-world data breaches happen due to OWASP vulnerabilities like SQL Injection, XSS, and Broken Access Control.

SQL Injection (SQLi)

SQL Injection is a vulnerability that occurs when user input is directly inserted into a database query without proper sanitization.

Attackers can:

  • Read sensitive data
  • Modify database records
  • Bypass authentication
  • Delete entire databases

Vulnerable SQL Query Example


SELECT * FROM users
WHERE username = 'admin'
AND password = '1234';

If user input is not sanitized, an attacker can manipulate this query.

Simple SQL Injection Example

Attacker input: 


admin' --

Resulting query becomes: 


SELECT * FROM users
WHERE username = 'admin' -- '
AND password = 'anything';

The -- turns the rest of the query into a comment, bypassing password check.

Security Insight

This is why all input must be parameterized using prepared statements.

UNION-Based SQL Injection

UNION-based SQL injection allows an attacker to combine results from multiple SELECT queries into a single response.

This technique is powerful when the application displays database output.

Example Payload


' UNION SELECT username, password FROM users --

How it works

The UNION keyword merges attacker-controlled query results with the original query output, exposing sensitive data.

Error-Based SQL Injection

This type of SQL injection forces the database to return errors that reveal internal structure or data.

Example Payload


' AND 1=CONVERT(int,(SELECT @@version)) --

If the database is misconfigured, it will return error messages containing useful information.

Security Insight

Modern systems should disable verbose error messages in production.

Boolean-Based Blind SQL Injection

In blind SQL injection, the application does not show database output. Instead, attackers rely on true/false responses.

Example Payloads


' AND 1=1 --
' AND 1=2 --

If the page behaves differently, it confirms the existence of a vulnerability.

Blind SQL Injection

Blind SQL injection happens when there is no visible error or output. Attackers extract data using indirect methods.

  • Time-based delays (SLEEP)
  • Boolean responses
  • Out-of-band channels

Time-Based Example


' AND IF(1=1, SLEEP(5), 0) --

If the response is delayed, it confirms that the injection worked.

Real-world usage

Blind SQLi is very common in real applications because developers hide database errors from users.

Authentication Bypass via SQL Injection

One of the most dangerous impacts of SQL injection is bypassing login systems.

Example


Username: admin' --
Password: anything

This modifies the SQL query logic and logs the attacker in without knowing the real password.

Security Insight

Proper authentication must use prepared statements instead of string concatenation.

Cross-Site Scripting (XSS)

XSS is a vulnerability that allows attackers to inject malicious scripts into web pages viewed by other users.

  • Reflected XSS → Input comes from request
  • Stored XSS → Stored in database
  • DOM-based XSS → Happens in browser (client-side)

Example Payload


<script>
alert('XSS Attack');
</script>

Security Insight

XSS can be used to steal cookies, hijack sessions, or perform actions on behalf of a user.

Cross-Site Request Forgery (CSRF)

CSRF forces a logged-in user to perform unwanted actions without their knowledge.

Attack Scenario

If a user is logged into a banking site, an attacker can trick them into submitting a request like: 


POST /transfer
amount=10000
to=attacker_account

Defense

CSRF tokens are used to prevent unauthorized requests.

Insecure Direct Object Reference (IDOR)

IDOR happens when an application exposes internal objects without proper authorization checks.

Example URL


https://site.com/profile?id=1001

Changing the ID may allow access to other users' data.

Security Insight

Always verify user permissions on the server side, not just the frontend.

Command Injection

Command injection occurs when user input is executed directly on the server operating system.

Vulnerable Example


ping 127.0.0.1; rm -rf /

If not sanitized, attackers can execute system commands.

Security Insight

Never pass user input directly to system shell commands.

Intermediate Level Summary

  • SQL Injection allows database compromise
  • XSS allows browser-side attacks
  • CSRF forces unwanted actions
  • IDOR exposes unauthorized data
  • Command Injection gives system control
